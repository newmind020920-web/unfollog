# Instafloww

인스타그램에서 **누가 나를 언팔로우했는지** 찾아주는 웹사이트입니다.

로그인도, 비밀번호도, 서버 업로드도 없습니다. 인스타그램이 공식으로 제공하는
"내 정보 다운로드" 파일을 브라우저에서 직접 읽고, 결과를 브라우저 안에만 저장합니다.

## 왜 이런 방식인가

"인스타 아이디/비밀번호를 입력하면 언팔로워를 알려준다"는 서비스는 전부
비공식 접근(스크래핑)입니다. 인스타그램 약관 위반이고, 사용자 계정이 정지되거나
탈취될 수 있습니다. 공식 Graph API 는 팔로워 목록 자체를 제공하지 않습니다.

남는 합법적인 방법은 하나뿐입니다 — 사용자가 **자기 데이터를 공식으로 내려받아**
직접 비교하는 것. 이 프로젝트가 하는 일이 그겁니다.

## 동작 원리

인스타그램 내보내기에는 **"지금" 팔로워가 누구인지**만 들어 있습니다. 과거 팔로워
기록은 없습니다. 그래서 파일 한 개로 언팔로워를 알아내는 건 원리적으로 불가능합니다.

Instafloww 는 올린 목록을 **스냅샷**으로 브라우저(IndexedDB)에 저장해 두고,
다음에 올린 파일과 비교합니다.

| 분석 | 필요한 스냅샷 |
| --- | --- |
| 언팔로워 (나를 언팔한 사람) | 2개 |
| 새 팔로워 | 2개 |
| 짝사랑 (내가 팔로우 → 상대는 안 함) | 1개 |
| 팬 (상대가 팔로우 → 내가 안 함) | 1개 |
| 맞팔 | 1개 |

## 데이터 내보내는 법

1. 인스타그램 → 설정 및 활동 → 내 정보 및 권한 → **내 정보 다운로드**
   ([바로가기](https://accountscenter.instagram.com/info_and_permissions/dyi/))
2. **"일부 정보 선택"** 에서 **팔로워 및 팔로잉**만 체크 (전체를 받으면 수 GB)
3. 형식 **JSON**, 기간 **전체 기간**
4. 받은 ZIP 을 압축 풀지 말고 그대로 업로드

## 개발

```bash
npm install
npm run dev        # 개발 서버
npm run test       # 파서 · 비교 로직 테스트 (28개)
npm run typecheck
npm run build      # dist/ 에 정적 파일 생성
```

빌드 결과는 순수 정적 파일이라 GitHub Pages, Vercel, Netlify, S3 어디든 그대로
올릴 수 있습니다. 백엔드가 필요 없습니다.

## 구조

```
src/
  lib/
    zip.ts       의존성 없는 ZIP 리더 (DecompressionStream, ZIP64 지원)
    parse.ts     인스타그램 내보내기 파서 (JSON / HTML, 분할 파일, 다른 관계 파일 제외)
    analyze.ts   맞팔 분석 · 스냅샷 비교
    db.ts        IndexedDB 스냅샷 저장소
    export.ts    CSV 내보내기
  components/    UI
  App.tsx        화면 구성
test/            파서 · 비교 로직 테스트
```

`zip.ts` 는 중앙 디렉터리만 먼저 읽어 필요한 JSON 몇 개만 꺼냅니다. 사진이 수 GB
들어 있는 내보내기 ZIP 을 올려도 메모리에 전부 올라가지 않습니다.

## 알려진 한계

- **아이디 변경**: 사용자명을 바꾼 계정은 "언팔로워 1명 + 새 팔로워 1명"으로
  보입니다. 앱에서 이 경우를 안내합니다.
- **탈퇴 · 비활성화 · 차단**: 이것도 언팔로워 목록에 섞여 들어갑니다. 내보내기
  파일만으로는 구분할 방법이 없습니다.
- **브라우저 데이터 삭제 시 스냅샷도 삭제됩니다.** 중요한 목록은 CSV 로 내려받아
  두세요.
